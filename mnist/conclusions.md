# Conclusions

## Fault model

We studied single-bit faults in the stored weights of a small MNIST digit classifier (784 inputs → 128 hidden units with ReLU → 10 outputs). It was trained in FP32 on the CPU, then converted to FP16 and run on the Mac GPU (Apple M5 Pro, PyTorch MPS). Faults went only into the two weight matrices, `fc1.weight` (128 × 784) and `fc2.weight` (10 × 128); biases were not faulted. From each matrix we picked 150 weights uniformly at random with no repeats, 300 in all. For each weight we flipped each of its 16 bits (0–15: bit 15 is the sign, bits 14–10 the exponent, bits 9–0 the mantissa) one at a time, giving 300 × 16 = 4,800 faults. Each fault was a single bit flipped directly in the weight's FP16 bits in the network's memory, with only one fault present at a time. It stayed in place while the network classified all 10,000 MNIST test images. We then classified the fault against the fault-free FP16 network's predictions: non-finite if any output score was infinity or NaN; otherwise silent data corruption (SDC) if at least one of the 10,000 predicted digits changed; otherwise masked. To restore, we wrote the weight's saved original bits back. A SHA-256 fingerprint of the whole matrix, taken before the flip and after the restore, had to match, or the run would stop. All randomness came from one master seed, 20261104, which numpy's `SeedSequence` split into separate streams: one for training (the starting weights and the shuffled order of training images each epoch), one for picking the step 4 weight (`fc1.weight` index 33719), and one each for picking the `fc1` and `fc2` samples. Evaluation used no randomness and always used the same 10,000 test images, so the same network gives the same scores every time. Two complete runs with the same seed produced byte-identical result files.
